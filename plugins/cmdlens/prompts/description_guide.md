# CmdLens Description Guide

Bash 도구를 사용할 때 **description** 필드에 다음 형식으로 작성하세요.

## 형식

```
📋 설명 | ⚠️ 위험도 | 💡 복구: 복구방법
```

## 위험도 기준 및 아이콘

| 레벨 | 아이콘 | 설명 | 예시 명령어 |
|------|--------|------|-------------|
| Safe | 🟢 | 읽기 전용, 정보 조회 | `ls`, `cat`, `pwd`, `echo`, `git status` |
| Caution | 🟡 | 파일 수정, 설정 변경 | `mv`, `cp`, `chmod`, `git commit` |
| Danger | 🔴 | 파일 삭제, 시스템 변경, 되돌리기 어려움 | `rm -rf`, `sudo`, `dd`, `git push --force` |

## 작성 가이드

### 📋 설명 작성법
- **무엇을 하는지** 명확하게 설명
- **대상 파일/폴더**가 있다면 언급
- **목적**이 있다면 간략히 추가
- 예시:
  - ❌ `파일 삭제` (너무 간단)
  - ✅ `temp 폴더의 캐시 파일들 삭제하여 디스크 공간 확보`

### 💡 복구 방법 작성법
- **구체적인 명령어**를 제시 (가능한 경우)
- 복구 불가능하면 **대안/주의사항** 제시
- 예시:
  - ❌ `불필요` (정보 없음)
  - ✅ `읽기 전용 작업으로 복구 불필요`
  - ❌ `불가능`
  - ✅ `삭제된 파일 복구 불가, 실행 전 백업 권장`

## 예시

### Safe (안전)
```
📋 현재 디렉토리의 파일 및 폴더 목록 조회 | 🟢 Safe | 💡 복구: 읽기 전용 작업으로 복구 불필요
📋 Git 저장소 상태 확인 (변경된 파일, 스테이징 상태) | 🟢 Safe | 💡 복구: 읽기 전용 작업으로 복구 불필요
📋 package.json 파일 내용 확인하여 의존성 파악 | 🟢 Safe | 💡 복구: 읽기 전용 작업으로 복구 불필요
```

### Caution (주의)
```
📋 config.js 파일을 backup 폴더로 이동 | 🟡 Caution | 💡 복구: mv backup/config.js ./config.js
📋 변경사항을 Git에 커밋하여 버전 기록 생성 | 🟡 Caution | 💡 복구: git reset HEAD~1 으로 커밋 취소 가능
📋 npm 패키지 설치하여 프로젝트 의존성 추가 | 🟡 Caution | 💡 복구: npm uninstall <패키지명>으로 제거 가능
```

### Danger (위험)
```
📋 node_modules 폴더 전체 삭제하여 클린 재설치 준비 | 🔴 Danger | 💡 복구: npm install로 재설치 가능하나 시간 소요
📋 원격 저장소에 강제 푸시하여 히스토리 덮어쓰기 | 🔴 Danger | 💡 복구: git reflog로 이전 상태 확인 후 복구 시도 가능
📋 시스템 설정 파일 수정 | 🔴 Danger | 💡 복구: 수정 전 원본 백업 필수, 복구 어려울 수 있음
```

## 규칙

1. **모든** Bash 명령어에 description을 작성합니다.
2. 위험도 아이콘은 반드시 `🟢 Safe`, `🟡 Caution`, `🔴 Danger` 중 하나를 사용합니다.
3. 설명은 **구체적이고 이해하기 쉽게** 작성합니다.
4. 복구 방법은 **실행 가능한 명령어**나 **구체적인 방법**을 제시합니다.
5. 사용자의 언어(한국어/영어)에 맞춰 작성합니다.
6. 파이프라인이나 복합 명령어는 가장 위험한 부분 기준으로 위험도를 판단합니다.
